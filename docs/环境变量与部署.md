# 环境变量与 PostgreSQL 部署约定

已实现配置加载器、启动器与 Dockerfile。以下命令供部署时使用，未执行 Docker 构建或运行测试；本地启动步骤见根 README。

## 数据库

使用 PostgreSQL。应用容器包含前端静态服务、Python API（内置 APScheduler）；数据库使用已有 PostgreSQL 或独立容器。

| 变量 | 含义 | 示例 |
| --- | --- | --- |
| DATABASE_URL | 驱动、主机、端口、库名，可附 TLS 参数；不包含用户名和密码 | postgresql+psycopg://postgres:5432/smsbot |
| DATABASE_USER | 数据库用户名 | smsbot |
| DATABASE_PASSWORD | 数据库密码 | 自行设置 |
| APP_SECRET | 应用密钥 | 部署时生成 |
| CREDENTIAL_ENCRYPTION_KEY | TOTP 与通知凭据的 Fernet 加密密钥 | 用 `python -m app.cli generate-secrets` 生成 |
| APP_ORIGIN | 浏览器访问的唯一来源，不带路径或末尾斜杠 | http://localhost:5173 |
| COOKIE_SECURE | 生产 HTTPS 必须为 true，本地 HTTP 开发为 false | true |
| DEVICE_POLL_MS | 设备空闲轮询间隔，最小 1000ms | 1000 |
| DEVICE_HEARTBEAT_MS | 设备状态上报间隔，最小 10000ms | 30000 |
| ALLOW_PRIVATE_NOTIFICATIONS | 是否允许自建内网通知服务 | false |

后端使用 SQLAlchemy URL 解析并通过 `URL.set(username=..., password=...)` 设置凭据，不直接拼接字符串。分离保存的密码无需 URL 编码，包含 `@`、`:` 等字符也必须正确处理；拒绝 URL 内嵌凭据，避免与独立变量产生歧义。日志不得输出密码或完整认证 URL。

开发启动从项目根目录读取 `.env`，文件路径不依赖启动时工作目录。优先级为：进程环境变量 > `.env` > 非敏感默认值。必需变量缺失、为空或仍为示例占位符时启动失败，不能静默回退到其他数据库。

## 文件与注入

复制根目录 `.env.example` 为 `.env`，填写实际值。文件采用 UTF-8；供 Docker `--env-file` 使用时采用 `KEY=value`，不使用 `export`、插值表达式或行尾注释，也不为值添加包装引号。值中的 `$` 按字面处理，后端读取器应保持同样语义；换行值不属于此文件格式。

按 Dockerfile 构建镜像后，可按以下方式启动；`smsbot-net` 需提前存在且能解析数据库主机名：

```sh
docker run -d --name smsbot --network smsbot-net --env-file .env -p 8080:8080 -p 8000:8000 smsbot:local
```

也可通过部署平台直接注入环境变量，或使用 `-e` 覆盖文件中的单项值：

```sh
docker run -d --name smsbot --network smsbot-net --env-file .env -e DATABASE_URL=postgresql+psycopg://db.internal:5432/smsbot -p 8080:8080 -p 8000:8000 smsbot:local
```

实际密码通过环境管理功能或受控文件注入，示例命令不写真实密码。Docker 支持 `--env-file` 与 `-e` 注入，参见 [官方文档](https://docs.docker.com/reference/cli/docker/container/run/)。

注意：应用容器中的 `localhost` 指应用容器自己。使用独立数据库容器时填写同一 Docker 网络的数据库服务名，使用外部数据库时填写可访问的域名/IP。

若以后提供 Compose，根目录 `.env` 的变量插值与容器环境注入是不同步骤，需显式配置服务的 `env_file` 或 `environment`。应用变量 `DATABASE_*` 不会自动初始化官方 PostgreSQL 容器；数据库部署方另行配置建库、用户及相应 `POSTGRES_*` 初始化变量。

## 启动与持久化

1. 数据库服务就绪，数据库与应用账户已经创建。
2. 应用校验配置，按有限次数重试数据库连接，失败后明确退出。
3. 通过单一迁移步骤执行 AQ-DBMigration，读取 `backend/resource/db_migration` 的版本 SQL，成功后启动 API 及内置调度器；首次 baseline 为 0。多实例部署需单独迁移任务或迁移锁，具体见 [数据库迁移](数据库迁移.md)。
4. PostgreSQL 数据由数据库服务持久化，应用镜像更新不影响数据库。
5. 备份 PostgreSQL 数据和加密主密钥，恢复后验证迁移版本及凭据解密。

远程数据库按服务方要求开启 TLS，校验证书时挂载相应 CA 文件。数据库配置只给后端使用，不能放入 `VITE_*` 变量或前端构建产物。前端使用同源 `/api`，无需访问数据库。

真实 `.env` 已加入 Git 与 Docker 忽略规则，固件也不进入应用镜像。Docker 构建和运行测试按用户要求不执行。
