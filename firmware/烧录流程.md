# LILYGO T-SIM7670G-S3 固件烧录流程

适用普通版 T-SIM7670G-S3（ESP32-S3、16MB Flash、8MB OPI PSRAM），不适用于 Standard 版。已通过 PlatformIO 编译，未连接实机烧录或验证运营商收发。

固件使用 Wi-Fi 连接平台，SIM7670G 负责短信。本文烧录 ESP32 应用，不升级 SIM7670G 模组固件。

## 1. 准备

安装 VS Code + PlatformIO IDE，打开 `firmware/`。也可安装 `python -m pip install platformio`，使用 `python -m platformio` 代替下文 `pio`。

用数据 USB 线连接 ESP32 的 USB-C 接口；Micro-USB 是模组升级接口。断电安装 SIM 和 LTE 天线再上电。SIM 需开通短信服务，LTE 联网不代表运营商一定支持该模组的短信业务。

参考：[LILYGO 普通版说明](https://github.com/Xinyuan-LilyGO/LilyGo-Modem-Series/blob/main/docs/en/esp32s3/sim7670g-s3/README.MD)。

## 2. 配置

先在平台「电话卡」→「添加手机号」填写号码并保存永久 API Key。已有卡片直接进入「API Key」签发或重置，无需重新添加。Key 不自动过期，可以稍后再接入设备。复制 `include/config.example.h` 为 `include/config.local.h`：

| 配置 | 内容 |
| --- | --- |
| WIFI_SSID / WIFI_PASSWORD | 2.4GHz Wi-Fi 名称和密码 |
| PLATFORM_URL | 可访问的 HTTPS 根地址，不带结尾 `/` 或 `/api` |
| ROOT_CA | 对应的可信 CA，PEM 格式 |
| PHONE_API_KEY | 对应手机号的永久 API Key |
| DEVICE_NAME | 预留配置，卡片名称以平台为准 |

固件通过 NTP 校准时间并验证 TLS。设备不能用 `localhost` 访问电脑；开发环境需要配置 HTTPS 入口。代码不使用 `setInsecure()` 回退。

本地配置已加入 Git 忽略。设备不需要数据库密码或管理员密码。真实配置会进入固件二进制，不要分发带私人凭据的构建产物。

## 3. 编译

在 `firmware/` 的 PlatformIO Core Terminal 执行：

```sh
pio run -e t-sim7670g-s3
```

已固定 ESP32 平台、ArduinoJson 与 PDUlib 提交。不要混用 Standard 引脚。项目分区为两个 3MB 应用区、约 9.94MB LittleFS 和独立 NVS。当前未提供远程 OTA 管理功能。

## 4. 首次初始化文件系统

```sh
pio device list
```

替换下文示例 `COM5` 为实际端口。**仅首次安装且没有待恢复短信时**执行：

```sh
pio run -e t-sim7670g-s3 --target uploadfs --upload-port COM5
```

这会覆盖 LittleFS 的现有短信队列。正常升级不要重复！挂载失败时固件停止工作并提示，不自动格式化。

## 5. 上传程序

```sh
pio run -e t-sim7670g-s3 --target upload --upload-port COM5
```

上传前关闭串口监视器。不能自动下载时，按住 ESP32 侧 BOOT 再上电，重新检查端口并上传；不要按模组的 SIM-BOOT。上传后释放 BOOT，必要时按 RST。

正常升级只编译并上传程序，保持分区布局，不覆盖文件系统，不全片擦除。PlatformIO 自动处理镜像偏移，无需手工指定裸 `.bin` 地址。

## 6. 查看连接

```sh
pio device monitor --port COM5 --baud 115200
```

程序读取 ICCID、连接 Wi-Fi、同步时间，用 PHONE_API_KEY 调用激活接口；Key 本身不变。重复激活安全，响应丢失可随时重试。普通重启复用保存的身份。

平台应出现电话卡、运营商、信号、SIM/网络状态。默认 30 秒心跳，超过 90 秒无心跳显示离线。空闲发信轮询为 1 秒，API 失败退避。串口不打印短信正文和完整凭据。

## 7. 收发验收

1. 从自己的手机给 SIM 发英文和中文短信，核对正文、发件人、电话卡、接收时间。
2. 长短信全部分片齐全后只上传一个完整事件。
3. 绑定通知通道，核对转发结果。
4. 平台向自己的手机发信，检查待发送 → 已领取 → 成功/失败。
5. 断网收信再恢复，应补传且不重复入库。
6. 重启后保留身份、待上传短信与待补交回执。

发信统一 UCS2，最多 670 个 BMP 字符，单条 70 字、分段 67 字（最多 10 片），暂不支持发送 emoji。部分分片成功后失败记为结果未知，不自动重发全文。成功表示模组确认提交，不等于收件人已收到。

接收最多保留 64 个本地消息组，每组最多 32 片。按发件人、拼接引用、总片数和短信服务中心时间（10 分钟窗口）重组，避免设备校时影响分片匹配；缺片保留并上报异常，不当作完整短信。缓存满、解析失败或持久化失败不删除 SIM 上的唯一副本。

## 8. 更新 Key 与换卡

重置 Key 后，旧 Key 对 API 和新固件均失效。把新 Key 写入 `PHONE_API_KEY`，重新编译并只上传程序；固件检测到 Key 变更会重新激活，保留 LittleFS 队列和待提交回执。删除 Key 会停止此 Key 的访问，想继续使用时在该手机号下重新签发。

首次升级旧配对固件时，将旧 `PAIRING_CODE` 配置替换为 `PHONE_API_KEY`，使用该卡平台页面签发的 Key。不要使用旧短期配对码。激活成功后旧版设备凭据失效。

换实体 SIM 时先处理完旧卡队列，在平台添加新手机号并签发新 Key。无待处理记录时可用串口 `PAIR RESET` 清除旧身份，然后配置新 Key、重新烧录。已有 ICCID 不会被另一张卡自动覆盖。移动原 SIM 到另一台板卡前，请先在原卡设置中解绑设备。
